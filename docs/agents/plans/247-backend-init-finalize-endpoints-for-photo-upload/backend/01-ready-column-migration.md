# `ready` column, two-step migration

Add the `ready` boolean column that distinguishes an in-flight upload
(row exists, file doesn't yet) from a displayable photo. Both rollout
steps land in this PR, per the issue discussion:

1. `add_column :photos, :ready, :boolean, default: true, null: false` —
   existing rows (and anything created before the rest of this plan
   ships) read as `ready: true`, matching today's implicit behavior. No
   backfill needed.
2. A second migration, applied after Steps 02–04 land in the same PR,
   flips the column default to `false` — the safe default for any
   future/other code path that doesn't set it explicitly. This step must
   come after `CreateItemPhotosJob` (Step 02) and Init (Step 03) both set
   `ready` explicitly, or newly-scanned photos would silently start as
   not-ready.

No change needed to `Oak::Photo`'s existing validations
(`source/app/models/oak/photo.rb`) — `ready` needs no presence/inclusion
validation, only the column default.

## Files to Change

- `source/db/migrate/<timestamp>_add_ready_to_photos.rb` — new migration,
  step 1 above.
- `source/db/migrate/<timestamp>_change_ready_default_on_photos.rb` — new
  migration, step 2 above (sequence its timestamp after Steps 02–04's
  code changes are written, even though the migration file itself is
  trivial).
- `source/db/schema.rb` — regenerated by running both migrations.
